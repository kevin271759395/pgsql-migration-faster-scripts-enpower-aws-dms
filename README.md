AWS DMS 针对同引擎（同构）PostgreSQL 迁移提供“转换或迁移至托管”（同构数据迁移）和“迁移和复制”两种方式。在源库结构标准、符合 AWS DMS 前提条件的情况下，推荐直接使用“转换或迁移至托管”完成迁移，无需额外脚本。但当源库存在触发器、或含无主键的 LOB 表等不满足 AWS DMS 直接迁移前提的情况时，需要配合脚本辅助或采用其他手工方案。
全手工 pg_dump/pg_restore 能保完整性但停机长、大库慢；手工逻辑复制停机短但不管次级对象、配置繁琐。本方案用 DMS 同构迁移（全量+CDC）保障“最小停机”，再用一套可复用脚本自动处理触发器、无主键 LOB 与次级对象补齐，在满足完整一致性的同时将停机窗口压到最小。
本方案基于源库存在触发器（加载时被触发会导致记录不一致）、含 text/jsonb 大字段但无主键/唯一约束等AWS DMS不能直接使用的场景，如果直接使用 AWS DMS “转换或迁移至托管”无法保证完整一致性。本方案通过脚本预建目标库结构、禁用触发器、迁移后补齐次级对象，配合同构迁移顺利完成。
在数据库停机时间方面，项目需要最小停机，业务系统不能长时间中断，要求切换停机窗口尽可能短。AWS DMS 同构迁移支持全量加载 + 增量同步（CDC），在实施时结合AWS DMS的特性进行方案设计，源库在全量与追增量期间保持在线可写，停机窗口仅为最后“停写 → 等增量追平 → 校验 → 切换”这一小段（通常分钟级）
